## Intent

Use Tavern for declarative API security regression tests that exercise HTTP
contracts, negative cases, status codes, response shapes, headers, and token
handling without requiring custom Python code for every request sequence.

## Context

Tavern is a pytest plugin, command-line tool, and Python library for automated
API testing with YAML syntax. Its documentation recommends using it with pytest:
install pytest and Tavern, write `.tavern.yaml` files, and run them through
pytest. It supports REST APIs and can use pytest fixtures and plugins.

This fits SatOIDC's security testing needs for endpoint-level contracts:
public/protected route boundaries, OAuth/OIDC error responses, token endpoint
negative cases, discovery/JWKS behavior, and LNURL callback failure handling.

## Scope

In scope:

- Adding Tavern as a development dependency.
- Adding a dedicated API security test task.
- YAML tests under `satoidc/tests/api/`.
- Reusable pytest fixtures for base URL, seeded users, seeded clients, and
  generated tokens where necessary.
- Negative security cases where request/response contracts are the important
  artifact.

Out of scope:

- Replacing Python pytest tests for complex stateful behavior.
- Browser UI testing.
- Load testing.
- Fuzz/property testing.
- Full OpenID certification conformance testing.

## Candidate Test Areas

- Public route boundary:
  - allowed public paths return expected status.
  - lookalike protected paths require authentication.
- OAuth/OIDC discovery:
  - discovery and JWKS endpoints return expected JSON fields and content types.
  - private key material is never exposed.
- Token endpoint negative cases:
  - missing grant type.
  - invalid client authentication.
  - invalid authorization code.
  - mismatched redirect URI.
  - missing or invalid PKCE verifier.
- UserInfo:
  - missing bearer token is rejected.
  - invalid bearer token is rejected.
  - valid token only exposes claims allowed by scopes.
- Revocation and introspection:
  - invalid client credentials fail closed.
  - revoked or unknown tokens do not appear active.
- LNURL callback:
  - malformed `k1`, `key`, and `sig` requests fail without authenticating or
    linking accounts.
- Security headers and response shape:
  - API errors do not include secrets, stack traces, password hashes, private
    keys, client secrets, or raw tokens.

## Rules

- Tavern tests must be marked `api_security`.
- Files must use `test_*.tavern.yaml` so pytest can discover them.
- Tests must run against an isolated local SatOIDC server and isolated test data.
- Tavern YAML must not contain committed secrets, production credentials, real
  tokens, or local `.env` values.
- Dynamic values such as authorization codes, access tokens, and client secrets
  must be generated by fixtures or setup stages and redacted from logs where
  possible.
- API security tests must assert both failure status and safe response content
  for negative cases.
- Tests that require containers must additionally use the integration/container
  marker and stay out of the default API security smoke command.

## Task Commands

- `poetry run task test_api_security`: `pytest -m api_security tests/api`

Optional full API contract command:

- `poetry run task test_api`: `pytest tests/api`

## Acceptance Criteria

- Given `poetry run task test_api_security` runs, then Tavern API security tests
  under `tests/api` are selected.
- Given a lookalike public route is requested, then the test proves it is not
  accidentally exposed by broad prefix matching.
- Given OAuth/OIDC negative requests are sent, then responses fail closed with
  expected status codes and no secret-bearing response bodies.
- Given discovery and JWKS are requested, then public metadata is present and
  private signing material is absent.
- Given malformed LNURL callback requests are sent, then no session, wallet
  link, or account registration is created.

## Implementation Notes

- Add `tavern` to the development dependency group.
- Add `api_security` and optionally `api_contract` markers to `pyproject.toml`.
- Reuse the existing live-server pattern from e2e tests where possible, without
  requiring a browser.
- Keep complex cryptographic setup in Python fixtures and keep Tavern YAML
  focused on HTTP request/response contracts.
